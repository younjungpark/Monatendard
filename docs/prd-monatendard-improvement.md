# Monatendard 개선 PRD

2026-10-01

## 요약

Monatendard의 영문을 Monaspace Neon 원본 그대로 되돌리고 한글을 균등 배율로 바꾼 시제품을 만들어, Jetendard만큼 편한지 판정한다. 통과하면 Monatendard v0.3.0으로 내고, 탈락하면 다른 영문 글꼴을 기반으로 별도의 새 폰트를 만든다.

시제품은 대조군이다. Monaspace는 셀이 넓고 소문자가 낮아 한글과의 크기 관계가 구조적으로 어긋나므로, 한글 이질감은 시제품으로 풀리지 않을 가능성이 있다. 순서는 시제품 확인이 먼저다. 시제품으로 개선 방향이 보이지 않을 때 다른 영문 글꼴과의 조합을 찾는다.

현재 상태: 1단계 시제품을 만들어 설치했고 판정을 기다린다. 진행 방법은 [시제품 판정 안내](proto-judgement.md)를 본다.

## 배경과 문제

Monatendard v0.2.3과 Jetendard를 번갈아 써 보니 Jetendard가 더 편했다. 불편한 지점은 영문 글자와 한글 글자 양쪽이고, Regular가 뭉쳐 보여 Light로 내려 쓰고 있다.

**기준 환경**: Windows Terminal, 2560×1440 모니터, 배율 100%(96 DPI). Jetendard는 14pt Regular, Monatendard는 15pt Light로 쓴다.

### Jetendard와의 실측 차이

Jetendard v0.1.0과 Monatendard v0.2.3의 Regular TTF를 fontTools로 측정한 값이다.

| 항목 (em 대비) | Jetendard | Monatendard v0.2.3 |
| --- | --- | --- |
| 기반 영문 글꼴 | JetBrains Mono 2.304 | Monaspace Neon Frozen 1.400 |
| 영문 처리 | 원본 그대로 | 가로 92.5%로 압축 후 다시 그림 |
| 영문 힌팅 | 있음 | 없음 |
| 영문 셀 폭 | 0.600 | 0.600 (원본 0.620) |
| x-height | 0.550 | 0.5135 |
| 영문 o 폭 × 높이 | 0.432 × 0.566 | 0.463 × 0.5375 (원본 폭 0.501) |
| 기본 줄 높이 | 1.320 | 1.245 |
| 한글 배율 | 균등 1.15 | 가로 1.13, 세로 1.11 |
| 한글 평균 크기 | 0.883 × 0.947 | 0.868 × 0.914 |
| 한글 힌팅 | 없음 | 없음 |
| 영문 세로획 / 한글 ㅣ | 0.090 / 0.088 | 0.088 / 0.087 |

### 원인 가설

- **영문 힌팅 소실이 가장 유력하다.** `builder.py`가 모든 영문 글리프를 다시 그리고 힌팅 테이블(`fpgm`, `prep`, `cvt`)을 지운다. 96 DPI에서는 힌팅이 없으면 획이 픽셀에 맞지 않아 흐려진다.
- **가로 92.5% 압축이 곡선을 왜곡한다.** 둥근 글자와 대각선 글자의 속공간이 좁아진다.
- **한글의 비균등 배율 자체는 작은 차이다.** 가로 1.13, 세로 1.11은 가로가 1.8% 더 늘어난 정도이고, 크기와 획 굵기는 Jetendard와 거의 같다. Jetendard도 Pretendard를 1.15배로 키워 쓴다.
- **x-height는 Monaspace 고유 설계라 고칠 수 없다.** 15pt Monatendard와 14pt Jetendard의 x-height가 같으므로, 크기를 올려 쓰는 것이 이미 보정이다.
- 줄 높이는 터미널 프로필의 `cellHeight`로 덮어쓰고 있어 체감 원인이 아니다.

이 가설들은 수치와 코드에서 나온 것이고, 실제 렌더링으로는 아직 검증하지 않았다. 시제품 판정이 그 검증이다.

### 한글 이질감의 구조적 원인

사용자가 꼽은 가장 큰 문제는 한글 비율을 조정하면서 생긴 이질감이다. 원인은 배율 값이 아니라 영문과 한글의 크기 관계로 보인다.

Monaspace Neon은 셀이 넓고(0.620em) 소문자가 낮다(x-height 0.5135). JetBrains Mono는 셀이 좁고(0.600em) 소문자가 높다(0.550). 그래서 Monaspace에서는 한글 크기를 어떻게 잡아도 한쪽이 어긋난다.

| 설정 | 한글 높이 ÷ 영문 x-height | 한글 글자 사이 여백 (셀 대비) |
| --- | --- | --- |
| Jetendard | 1.72 | 26% |
| Monatendard v0.2.3 | 1.78 | 28% |
| 균등 1.15, 1.240em 셀 | 1.84 | 29% |
| 균등 1.19, 1.240em 셀 | 1.91 | 26% |
| 균등 1.07, 1.240em 셀 | 1.72 | 33% |

- 한글로 셀을 채우면 영문 대비 한글이 커진다.
- 크기 관계를 Jetendard에 맞추면 한글 사이가 휑해진다.
- 균등 1.19는 키가 큰 글자가 세로 한계(0.945em)를 넘어 그 글자들만 따로 축소되므로 쓸 수 없다.

커밋 이력의 한글 세로 108% → 110% → 111% 조정과 영문 92.5% 압축은 이 어긋남을 배율로 메우려던 시도였다. 배율로는 풀 수 없는 문제다.

## 요구사항: 1단계 시제품

Monaspace Neon을 유지한 채 왜곡만 없애는 시제품이다. 변수를 적게 바꿔야 원인을 가릴 수 있으므로, 바꾸는 것은 영문 처리와 한글 배율 두 가지뿐이다.

| 항목 | v0.2.3 | 시제품 |
| --- | --- | --- |
| 영문 외곽선 | 가로 92.5% 압축 | 원본 그대로, 다시 그리지 않음 |
| 영문 힌팅 | 삭제 | 원본 보존 |
| 영문 셀 폭 | 0.600em | 0.620em |
| 한글 셀 폭 | 1.200em | 1.240em (영문의 정확히 2배) |
| 한글 배율 | 가로 1.13, 세로 1.11 | 균등 1.15 (Proto A), 균등 1.07 (Proto B) |
| 기본 줄 높이 | 1.245 | 1.245 (변경 없음) |
| 한글 힌팅 | 없음 | 없음 (변경 없음) |

**산출물**

- 패밀리 2개: `Monatendard Proto A`, `Monatendard Proto B`. 기존 v0.2.3과 나란히 설치할 수 있도록 이름을 다르게 한다.
    - Proto A(1.15)는 Jetendard와 같은 한글 크기다. 영문 대비 한글이 커진다.
    - Proto B(1.07)는 Jetendard와 같은 한글 대 영문 크기 관계다. 한글 사이 여백이 33%로 넓어진다. 이 여백이 받아들일 만한지를 확인한다.
- 굵기 3종: Light, Regular, Bold. 정체만 만든다.
- Nerd Font Mono 변형만 만든다.
- 리가처와 texture healing은 영문을 건드리지 않으므로 원본 그대로 남는다.

**설치**

- Windows에 사용자 단위로 설치한다. 관리자 권한은 쓰지 않는다.
- Windows Terminal의 `settings.json`은 수정하지 않고, 프로필에 넣을 설정 조각만 제공한다.
- 기존 프로필의 `cellWidth: 0.6`은 시제품 프로필에서 뺀다.

**받아들인 비용**: 셀이 넓어져 한 줄에 들어가는 글자 수가 약 3% 준다.

## 판정 절차

판정은 래스터 비교와 실사용 두 단계로 한다. 대체 후보 글꼴의 측정과 비교는 시제품이 탈락한 뒤에 시작한다.

1. **래스터 비교 이미지**: 20px, 96 DPI 조건으로 같은 코드와 한글 문장을 그려 한 장에 놓는다. 대상은 v0.2.3, Proto A, Proto B, Jetendard, Monaspace Neon 원본(영문만)이다.
2. **실사용**: Windows Terminal에서 며칠 쓴다. Regular로 돌아갈 수 있는지도 함께 본다.
3. **결정**: 그래도 Jetendard로 손이 가는지로 가른다.
    - 통과: 선택한 한글 배율(A 또는 B)로 Monatendard v0.3.0을 낸다.
    - 탈락: Monatendard는 v0.2.3 그대로 두고, 대체 기반 글꼴로 별도 이름의 새 폰트를 만든다.
    - 한글만 흐림: 한글 자동 힌팅을 별도 실험으로 시도한 뒤 다시 판정한다.

판정이 끝날 때까지 시제품은 릴리스하지 않는다.

## 대체 기반 글꼴 조건

Monaspace가 탈락할 경우 새 폰트의 영문 기반은 아래 네 가지를 모두 만족해야 한다. 앞의 두 폭·x-height 조건이 한글 이질감의 구조적 원인을 직접 푸는 조건이므로, 이 경로가 본론이 될 가능성이 크다.

| 조건 | 이유 |
| --- | --- |
| 원래 0.600em 폭으로 설계됨 | 외곽선을 누르지 않고도 한글 1.200em 셀에 맞는다 |
| 힌팅 내장 | 96 DPI에서 선명하게 보인다 |
| x-height 0.53em 이상 | 소문자가 Jetendard만큼 크게 보인다 |
| 기존 한글 합본이 없음 | 이미 있는 폰트를 다시 만들지 않는다 |

라이선스는 병합과 재배포가 가능한 OFL 계열이어야 한다.

**이미 제외된 글꼴**: JetBrains Mono(Jetendard), Geist Mono(Yeomil Mono), IBM Plex Mono(Monoplex KR).

**후보 선정 방식**: 시제품이 탈락하면 Commit Mono, Cascadia Code, Fira Code, Maple Mono 등을 대상으로 폭, 힌팅, x-height를 측정한다. 조건을 통과한 것만 래스터 비교 이미지에 영문만 올려 비교한다. 이 후보들의 수치는 아직 측정하지 않았다.

## 구현 범위

**빌더 (`src/monatendard/builder.py`)**

- 영문 배율이 1.0이고 셀 폭이 원본과 같으면 글리프를 다시 그리지 않고 힌팅 테이블도 지우지 않는다. 현재는 `scale_latin_horizontally`가 무조건 다시 그린다.
- 한글 병합에 균등 배율 경로를 쓴다. `_fit_cjk_transform`이 이미 있다.
- 패밀리 이름과 배율을 설정으로 바꿔 Proto A와 Proto B를 따로 빌드할 수 있게 한다.

**Nerd 병합 (`src/monatendard/nerd.py`)**

- 아이콘을 0.620em 셀에 맞춘다.

**검증과 테스트**

- 셀 폭 0.600em을 전제로 한 `verify` 검사와 테스트를 시제품 설정도 통과하도록 고친다.
- 박스 문자와 Powerline 글리프의 이음새가 0.620em 셀에서 맞는지 확인한다.
- 시제품 TTF에 영문 힌팅이 남아 있는지 검사를 추가한다.

**작업 방식**

- `main`이 아닌 실험 브랜치에서 작업한다.
- 커밋과 푸시는 요청이 있을 때만 한다.

## 미룬 것과 위험

**판정 후로 미룬 것**

- 한글 자동 힌팅 실험
- v0.3.0의 전체 범위: 이탤릭, 14개 스타일, 웹폰트, 설치 패키지, README 수치
- 새 폰트의 기반 글꼴 선정과 이름

**미해결 질문**

- 실사용 기간을 며칠로 할지 정하지 않았다.
- 래스터 비교를 어떤 렌더러로 그릴지 정하지 않았다. Windows Terminal과 같은 DirectWrite 결과여야 판정에 의미가 있다.

**위험**

- **한글 이질감은 시제품으로 풀리지 않을 가능성이 높다.** 원인이 Monaspace의 셀 폭과 x-height에 있어 배율로는 해결되지 않는다. Proto A와 B 모두 한쪽이 어긋난 채로 남는다. Proto B의 넓은 한글 간격이 눈에 괜찮은지가 관건이고, 아니면 대체 기반 선정으로 넘어간다.
- **힌팅 가설이 틀릴 수 있다.** 불편함이 Monaspace의 낮은 x-height나 글자 모양 자체에서 온다면 시제품으로도 해결되지 않는다. 이 경우가 곧 탈락 경로다.
- **한글은 여전히 무힌팅이다.** 영문만 선명해지면 한글과의 선명도 차이가 더 눈에 띌 수 있다. Jetendard도 같은 조건이다.
- **이탤릭의 박스 문자.** v0.2.3은 이탤릭에 정체의 박스 문자를 다시 그려 넣는다. 영문을 건드리지 않는 방식에서는 이 처리를 다시 설계해야 한다. v0.3.0 단계의 일이다.
- **대체 조건을 통과하는 글꼴이 적을 수 있다.** 네 조건을 모두 만족하는 후보가 없으면 조건을 다시 논의한다.

### 인터뷰 후 수정 (2026-10-01)

사용자가 가장 큰 문제로 한글 비율 조정에서 오는 이질감을 꼽아 다시 계산했고, 아래를 바꿨다.

- Proto B의 한글 배율을 균등 1.19에서 균등 1.07로 바꿨다. 1.19는 한글을 영문 대비 더 키우고, 키 큰 글자가 세로 한계를 넘는다.
- 순서를 시제품 먼저로 정했다. 시제품으로 개선 방향이 보이지 않을 때 다른 영문 글꼴과의 조합을 찾는다. Q17(후보를 래스터 비교에 지금 같이 넣음)은 이 결정으로 대체된다.
- 한글 이질감의 구조적 원인을 배경과 위험에 추가했다.
